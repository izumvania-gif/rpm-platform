# Состояние проекта

Снимок на 7 августа 2026 — релиз 1.0. Короткие характеристики для тех, кто впервые открывает репозиторий или готовит демо/custdev-звонок. Подробности — в README, `docs/user-guide/`, `plans/backlog.md` и `plans/ui-improvement-plan.md`.

## Что это

**RPM Platform** — репозиторий продуктового дискавери для одного продакт-менеджера: исследования → сегменты → JTBD (иерархия + граф) → гипотезы → CustDev-разговоры → инсайты, плюс слой позиционирования (конкуренты, фичи, RTB/«Маркетинг»). Не чат-ассистент и не ИИ-инструмент — структурированный реляционный репозиторий, куда данные вносит сам пользователь.

## Готовность

**1.0 — готово к демо и custdev-звонкам.** Полный CRUD на 10 моделях, инлайн-редактирование, граф JTBD с независимой раскладкой по сегментам, kanban гипотез, мастер онбординга нового продукта, отчёты (матрица Сегменты×JTBD, дашборд пробелов), глобальный поиск, фирменная визуальная идентичность («Реестр»). Детальный ретест перед этим релизом (см. `plans/ui-improvement-plan.md`) не нашёл ни одного функционального бага.

## Стек в одну строку

Next.js 14 (App Router) + React 18 + TypeScript, PostgreSQL + Prisma, TailwindCSS + shadcn/ui, NextAuth (сконфигурирован, не задействован), Zod, React Flow (граф JTBD) — единственная нетривиальная UI-зависимость. Подробности — README «Технологический стек».

## Цифры

- 11 моделей данных в `prisma/schema.prisma` (10 CRUD-модулей + `ProductResource`), плюс 4 вспомогательные (история статуса гипотезы, рёбра последовательности JTBD, позиции графа по представлению, лог новостей конкурента).
- 10 детальных страниц с инлайн-редактированием.
- Демо-продукт «Рутокен CLM» на основе реального сейл-кита — сегменты, JTBD с иерархией, гипотезы, разговоры, конкуренты, фичи, RTB, инсайты.
- Нет автотестов, нет CI — осознанное решение на этой стадии, см. `plans/backlog.md`.

## Однопользовательский режим

Все данные читаются/пишутся под одним захардкоженным пользователем (`lib/current-user.ts`). Экраны логина не построены. Не разворачивайте как общий инструмент команды, рассчитывая на разграничение доступа — авторизация и мультитенантность в бэклоге, не начаты.

## Самые заметные известные ограничения

- Тёмная тема: CSS-токены готовы, но не активируются никак — ни автоматически по системной настройке, ни вручную (нет переключателя). См. `plans/ui-improvement-plan.md`, приоритет 1.
- Мобильная навигация не сворачивается в гамбургер на узких экранах — платформа рассчитана в первую очередь на десктоп.
- ИИ-функций нет вовсе — ни AI-чата, ни автогенерации гипотез/инсайтов из транскриптов. Осознанно вне объёма текущей версии, см. `plans/backlog.md`.
- Массового импорта данных нет — каждая запись вносится через форму по одной.
