# Состояние проекта

Снимок на 7 августа 2026 — релиз 1.0 (тег `v1.0`). Короткие характеристики для тех, кто впервые открывает репозиторий или готовит демо/custdev-звонок. Подробности — в README, `docs/user-guide/`, `plans/backlog.md` и `plans/ui-improvement-plan.md`.

**Эта ветка (`2.0`) — поверх релиза 1.0**, с работой по `plans/platform-views-plan.md`. Остальной текст этого файла описывает базу 1.0, общую для обеих веток; 2.0-специфичное отмечено отдельно (см. «2.0 в разработке» ниже).

## Что это

**RPM Platform** — репозиторий продуктового дискавери для одного продакт-менеджера: исследования → сегменты → JTBD (иерархия + граф) → гипотезы → CustDev-разговоры → инсайты, плюс слой позиционирования (конкуренты, фичи, RTB/«Маркетинг»). Не чат-ассистент и не ИИ-инструмент — структурированный реляционный репозиторий, куда данные вносит сам пользователь.

## Готовность

**1.0 — готово к демо и custdev-звонкам.** Полный CRUD на 10 моделях, инлайн-редактирование, граф JTBD с независимой раскладкой по сегментам, kanban гипотез, мастер онбординга нового продукта, отчёты (матрица Сегменты×JTBD, дашборд пробелов), глобальный поиск, фирменная визуальная идентичность («Реестр»). Детальный ретест перед этим релизом (см. `plans/ui-improvement-plan.md`) не нашёл ни одного функционального бага.

**Визуальный редизайн завершён** (см. `plans/archive/visual-redesign-plan.md`) — все 4 фазы сделаны: токены (палитра, типографика, тёмная тема), примитивы `components/ui/*` (Select на Radix, Button/Card/Badge/Input/Textarea, иконки на модулях дашборда), «герои» (редизайн карточки узла JTBD-графа, дашборд как композиция, kanban-карточки со статус-иконкой и датой, видимый оверлей клавиатурных сокращений), и проход по хвосту — формы в 2 колонки на широких экранах, более выразительный активный таб в `SiteNav`, сетки карточек на 5 страницах списков (`/segments`, `/competitors`, `/insights`, `/features`, `/marketing`) заменены на плотные hairline-списки.

**Редизайн дашборда завершён** (см. `plans/archive/dashboard-redesign-plan.md`) — все 4 фазы сделаны: общий слой метрик (`lib/dashboard-metrics.ts`, переиспользуемый `/reports/gaps` и `/jtbd`), инфраструктура кастомизации (виджеты можно скрывать и перетаскивать через панель «Настроить дашборд», раскладка сохраняется в браузере), четыре actionable-виджета с графиками — gaps-сводка, meter покрытия JTBD, воронка гипотез (stacked bar), спарклайн частоты исследований — все на самодельном inline-SVG без новых зависимостей, и разгрузка: 9 крупных карточек-плиток заменены на компактную горизонтальную навигационную плашку (`ModuleRail`) над виджетами.

**2.0 в разработке** (ветка `2.0`, см. `plans/platform-views-plan.md`) — Фазы 0–1 сделаны. Фаза 0: справочник `Person` (`/people`, полный CRUD с инлайн-редактированием, без inline-create и без дублирования/CSV — осознанно урезано до реально нужного на этом шаге), `Product.ownerId`/`Product.publicSummary`, каркас переключателя ролей в `SiteNav` («Представления» → 5 маршрутов). Явно не граница доступа — см. предупреждение прямо в самом переключателе. Фаза 1: модель `RoadmapItem` (статус/квартал/видимость, опциональные связи с человеком/фичей/JTBD), без отдельной detail-страницы — тот же паттерн, что у `ProductResource`; `/pm` стал настоящей страницей (переключатель продукта + роадмап выбранного продукта по кварталам), «Команда»/«Процесс» на ней — честные заглушки «скоро». `/cpo`, `/public`, `/marketing-hub`, `/sales-hub` пока заглушки. Остальные фазы (командный дашборд, диаграмма процессов + экшн-планы, открытый дашборд компании, CPO, маркетинг- и продажи-хабы) не начаты.

## Стек в одну строку

Next.js 14 (App Router) + React 18 + TypeScript, PostgreSQL + Prisma, TailwindCSS + shadcn/ui, NextAuth (сконфигурирован, не задействован), Zod, React Flow (граф JTBD) — единственная нетривиальная UI-зависимость. Подробности — README «Технологический стек».

## Цифры

- 11 моделей данных 1.0 в `prisma/schema.prisma` (10 CRUD-модулей + `ProductResource`), плюс 4 вспомогательные (история статуса гипотезы, рёбра последовательности JTBD, позиции графа по представлению, лог новостей конкурента) — плюс `Person` и `RoadmapItem` (2.0, см. `CLAUDE.md`).
- 10 детальных страниц 1.0 с инлайн-редактированием, плюс `/people/[id]` (2.0); `RoadmapItem` намеренно без своей — рендерится инлайн на `/pm`.
- Демо-продукт «Рутокен CLM» на основе реального сейл-кита — сегменты, JTBD с иерархией, гипотезы, разговоры, конкуренты, фичи, RTB, инсайты.
- Тесты (на момент Фазы 1 ветки `2.0`): 21 unit + 115 integration + 29 E2E (Vitest + Playwright), CI на GitHub Actions гоняет всё на каждый push/PR — см. `## Testing` в `CLAUDE.md`. Деплой/CD не настроен — нет ещё выбранной площадки хостинга.

## Однопользовательский режим

Все данные читаются/пишутся под одним захардкоженным пользователем (`lib/current-user.ts`). Экраны логина не построены. Не разворачивайте как общий инструмент команды, рассчитывая на разграничение доступа — авторизация и мультитенантность в бэклоге, не начаты.

## Самые заметные известные ограничения

- Мобильная навигация не сворачивается в гамбургер на узких экранах — платформа рассчитана в первую очередь на десктоп.
- ИИ-функций нет вовсе — ни AI-чата, ни автогенерации гипотез/инсайтов из транскриптов. Осознанно вне объёма текущей версии, см. `plans/backlog.md`. Черновой план подключения (без реализации) — `plans/ai-implementation-plan.md`, обоснование приоритетов — `plans/pm-time-allocation-research.md`.
- Массового импорта данных нет — каждая запись вносится через форму по одной.
