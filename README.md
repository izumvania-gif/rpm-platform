# RPM Platform

Платформа для product discovery: репозиторий клиентских исследований, сегменты, JTBD (с иерархией и визуальным графом, включая независимые графы по сегментам), гипотезы, CustDev-разговоры и слой позиционирования продукта (конкуренты — с логом новостей, фичи, RTB/«Маркетинг»).

> **Релиз 1.0** (7 августа 2026). Короткий снимок того, что реально построено — [`PROJECT_STATE.md`](./PROJECT_STATE.md). Что осознанно отложено — [`plans/backlog.md`](./plans/backlog.md). Найденные при 1.0-ретесте возможности улучшить UI — [`plans/ui-improvement-plan.md`](./plans/ui-improvement-plan.md). Вся история планирования (включая ребрендинг ECHO → RPM Platform и исходный спек под старым именем) — в [`plans/archive/`](./plans/archive/README.md).

**Если вы пользователь, а не разработчик** — начните с [`docs/user-guide/`](./docs/user-guide/README.md): как продакт-менеджер использует платформу день в день, пошаговые сценарии и рекомендации. Всё, что ниже в этом файле, — для тех, кто разворачивает или дорабатывает платформу.

## Технологический стек

- **Frontend:** Next.js 14 (App Router), React 18, TypeScript — fullstack-монолит, отдельного backend-сервиса нет
- **Styling:** TailwindCSS, shadcn/ui, фирменный красно-белый стиль ("Rutoken corporate") через CSS-переменные. Токены тёмной темы полностью готовы, но **пока нигде не активируются** (ни автоматически по `prefers-color-scheme`, ни переключателем) — см. `plans/ui-improvement-plan.md`
- **Database:** PostgreSQL 15+ через Prisma ORM (`prisma db push`, без миграций в dev-режиме)
- **Authentication:** NextAuth.js (Credentials provider), сейчас все данные фактически ведутся под одним захардкоженным пользователем — многопользовательский режим не задействован
- **Валидация:** Zod
- **Граф JTBD:** `@xyflow/react` (React Flow) — единственная нестандартная зависимость UI

`@tanstack/react-query` и `react-hook-form` установлены в `package.json`, но нигде не используются — формы построены на нативных Server Actions + `useTransition`, без клиентского стейт-менеджера. Не полагайтесь на эти пакеты как на часть архитектуры.

## Начало работы

### Предварительные требования

- Node.js 20+
- PostgreSQL 15+
- npm

### Установка

1. Клонируйте репозиторий:

```bash
git clone <repository-url>
cd rpm-platform
```

2. Установите зависимости:

```bash
npm install
```

3. Настройте переменные окружения:

```bash
cp .env.example .env.local
```

Отредактируйте `.env.local` и укажите правильные данные для подключения к PostgreSQL.

4. Инициализируйте базу данных и загрузите демо-данные:

```bash
npm run db:push
npm run db:seed
```

5. Запустите сервер разработки:

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) в браузере.

## Доступные команды

- `npm run dev` — запуск сервера разработки
- `npm run build` — сборка для production
- `npm run start` — запуск production сервера
- `npm run lint` — проверка кода линтером
- `npm run format` — форматирование кода с помощью Prettier
- `npm run db:push` — синхронизация схемы Prisma с БД (без файла миграции — используется в dev)
- `npm run db:migrate` — создание и применение миграции
- `npm run db:generate` — генерация Prisma Client
- `npm run db:studio` — Prisma Studio GUI

Автотестов пока нет — осознанное решение на текущем этапе (см. [`plans/backlog.md`](./plans/backlog.md)).

## Структура продукта

```
Продукты    Сегменты   Исследования   Маркетинг   JTBD
  │                        │          (было RTB)    │
  ├─ Конкуренты            ├─ Гипотезы               ├─ Список
  └─ Фичи                  ├─ Разговоры               └─ Граф (общий + по сегментам)
                           └─ Инсайты
```

5 главных табов вместо прежнего плоского списка из 9 пунктов. У «Продуктов» и «Исследований» есть выпадающее под-меню (наведение/фокус), у JTBD — переключатель "Список"/"Граф" на самой странице раздела, а сам граф дополнительно переключается между общим представлением и графом конкретного сегмента (у каждого — своя независимая раскладка узлов). Конкуренты — под-пункт меню «Продукты», рядом с «Фичи» (маршрут `/competitors` не менялся, просто теперь виден в навигации). RTB переименован в "Маркетинг" в навигации и заголовках (маршрут `/rtb` → `/marketing`; Prisma-модель осталась `RTB`). В шапке есть поле поиска (`/search?q=`) по всем модулям. Отдельно от этой навигации — `/reports` (не в верхнем меню): матрица "Сегменты × JTBD" и дашборд пробелов, аналитические read-only страницы поверх уже собранных данных.

## Текущее состояние

Реализовано и работает:

- **11 моделей данных**: Product, Research, Segment, JTBD (+граф последовательности, +персистентные позиции узлов по представлению), Hypothesis (+история статусов), Conversation, Competitor (+лог новостей), ProductResource, Feature, RTB, Insight — методологическое ядро JTBD → Feature → RTB собрано целиком.
- **Граф JTBD** (`/jtbd/graph`, React Flow): иерархия задач с перетаскиванием, связи "следует за", 4 типа задач (big/core/small/micro job) с цветовой легендой, инлайн-добавление узла прямо на канвасе. JTBD↔Сегмент — связь многие-ко-многим; у графа есть переключатель между общим представлением продукта и графом конкретного сегмента, у каждого представления — независимо сохраняемая раскладка узлов (кнопка «Автоматически расставить» пересчитывает только текущее представление).
- **Kanban гипотез** (`/hypotheses`): перетаскивание карточек между статусами, нативный HTML5 Drag and Drop.
- **Инлайн-редактирование** — клик по значению скалярного поля на любой из 10 детальных страниц превращает его в инпут на месте (без перехода на отдельную форму); поля-связи по-прежнему редактируются через полную форму.
- **Конкурент**: лог новостей/наблюдений (простой CRUD-подсписок) и доп. атрибуты (модель ценообразования, размер компании, дата последней проверки).
- **Фильтры фич** по JTBD и сегменту.
- **Фирменный красно-белый стиль** («Реестр» — сквозная нумерация записей + сигнальные цвета типов/статусов), карточная группировка на странице продукта, дашборде и списках Конкурентов/Фич/Маркетинга/Инсайтов (группировка по продукту).
- **5-табовая навигация** с выпадающими под-меню (Продукты → Фичи, Конкуренты; Исследования → Гипотезы, Разговоры, Инсайты) и переключателем "Список"/"Граф" на JTBD.
- **Инсайты** (`/insights`): атомарные цитаты и выводы из исследований/разговоров с привязкой к сегменту и/или JTBD — отдельно от полного транскрипта.
- **Отчёты** (`/reports`): матрица "Сегменты × JTBD" (доля JTBD, подтверждённых исследованиями, по сегментам и категориям, с корректным учётом многосегментных JTBD) и дашборд пробелов (неподтверждённые JTBD, сегменты без задач, зависшие гипотезы, продукты без свежих исследований).
- **Глобальный поиск** (`/search?q=`): по всем 11 моделям сразу, поле в шапке.
- **Мастер настройки нового продукта** (`/products/[id]/onboarding/*`): необязательный выбор при создании продукта («Создать» vs «Создать и настроить →»), 6 шагов (Сегменты → JTBD → Исследования/Разговоры/Инсайты → Гипотезы → Конкуренты → Фичи и RTB) + страница-рекап, с возможностью пропустить в любой момент.
- **Мелкие удобства**: закреплённые записи, дублирование записи, CSV-экспорт, копирование ссылки, версия для печати, лента активности, клавиатурные сокращения.
- **Демо-данные**: полностью заполненный продукт «Рутокен CLM» на основе реального сейл-кита.

Осознанно не реализовано на этом этапе (решения продакт-менеджера, не пробелы) и что дальше — см. [`plans/backlog.md`](./plans/backlog.md). Найденные при финальном ретесте UI-улучшения (не баги) — [`plans/ui-improvement-plan.md`](./plans/ui-improvement-plan.md).
