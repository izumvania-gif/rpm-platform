# RPM Platform

Платформа для product discovery: репозиторий клиентских исследований, сегменты, JTBD (с иерархией и визуальным графом, включая независимые графы по сегментам), гипотезы, CustDev-разговоры и слой позиционирования продукта (конкуренты — с логом новостей, фичи, RTB/«Маркетинг»).

> **Релиз 1.0** (7 августа 2026, тег `v1.0`) — на ветке `main`. **Ветка `2.0`** ушла дальше: ролевые представления (PM/CPO/открытый дашборд/маркетинг/продажи), массовый ввод и импорт, холст продукта, инбокс и проход по технической устойчивости — тега пока нет, всё описано в `plans/2.0-*.md`. Короткий снимок того, что реально построено — [`PROJECT_STATE.md`](./PROJECT_STATE.md). Что осознанно отложено — [`plans/backlog.md`](./plans/backlog.md). Вся история планирования (включая ребрендинг ECHO → RPM Platform и исходный спек под старым именем) — в [`plans/archive/`](./plans/archive/README.md).

**Если вы пользователь, а не разработчик** — начните с [`docs/user-guide/`](./docs/user-guide/README.md): как продакт-менеджер использует платформу день в день, пошаговые сценарии и рекомендации. Всё, что ниже в этом файле, — для тех, кто разворачивает или дорабатывает платформу.

## Технологический стек

- **Frontend:** Next.js 14 (App Router), React 18, TypeScript — fullstack-монолит, отдельного backend-сервиса нет
- **Styling:** TailwindCSS, shadcn/ui, фирменный красно-белый стиль ("Rutoken corporate") через CSS-переменные. Тёмная тема работает: по умолчанию следует `prefers-color-scheme`, переключается кнопкой в шапке, выбор хранится в `localStorage` и применяется до гидрации инлайн-скриптом в `app/layout.tsx` (без мигания светлой темы)
- **Database:** PostgreSQL 15+ через Prisma ORM (`prisma db push`, без миграций в dev-режиме)
- **Authentication:** NextAuth.js (Credentials provider), сейчас все данные фактически ведутся под одним захардкоженным пользователем — многопользовательский режим не задействован
- **Валидация:** Zod
- **Графы и канвасы:** `@xyflow/react` (React Flow) — единственная нестандартная зависимость UI; на ней построены граф JTBD, холст продукта и диаграмма процесса
- **Тесты:** Vitest (unit + integration против настоящего PostgreSQL) и Playwright (E2E), CI — GitHub Actions

`@tanstack/react-query` и `react-hook-form` установлены в `package.json`, но нигде не используются — формы построены на нативных Server Actions + `useTransition`, без клиентского стейт-менеджера. Не полагайтесь на эти пакеты как на часть архитектуры.

## Начало работы

### Предварительные требования

- Node.js 20+
- PostgreSQL 15+
- npm

### Установка

1. Клонируйте репозиторий:

```bash
git clone <repository-url>
cd rpm-platform
```

2. Установите зависимости:

```bash
npm install
```

3. Настройте переменные окружения:

```bash
cp .env.example .env.local
```

Отредактируйте `.env.local` и укажите правильные данные для подключения к PostgreSQL.

4. Инициализируйте базу данных и загрузите демо-данные:

```bash
npm run db:push
npm run db:seed
```

5. Запустите сервер разработки:

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) в браузере.

## Доступные команды

- `npm run dev` — запуск сервера разработки
- `npm run build` — сборка для production
- `npm run start` — запуск production сервера
- `npm run lint` — проверка кода линтером
- `npm run format` — форматирование кода с помощью Prettier
- `npm run db:push` — синхронизация схемы Prisma с БД (без файла миграции — используется в dev)
- `npm run db:migrate` — создание и применение миграции
- `npm run db:generate` — генерация Prisma Client
- `npm run db:studio` — Prisma Studio GUI
- `npm run typecheck`, `npm run test`, `npm run test:integration`, `npm run test:e2e` — см. «Тесты» ниже

### Тесты

- `npm run typecheck` — `tsc --noEmit`
- `npm run test` / `npm run test:unit` — Vitest по чистым функциям, база не нужна
- `npm run test:integration` — Vitest по всем Server Actions против настоящего PostgreSQL
- `npm run test:e2e` — Playwright по реальным пользовательским сценариям в браузере

Интеграционным и E2E-тестам нужна **отдельная** тестовая база: скопируйте
`.env.test.example` в `.env.test`, создайте базу и один раз выполните против неё
`npm run db:push`. Обе связки откажутся стартовать, если в `DATABASE_URL` нет
подстроки «test» — защита от того, чтобы случайно вычистить рабочую базу.
Подробности — раздел `## Testing` в [`CLAUDE.md`](./CLAUDE.md).

CI (`.github/workflows/ci.yml`) гоняет линт, typecheck, все три уровня тестов и
production-сборку на каждый push и pull request.

## Структура продукта

```
Продукты      Сегменты   Исследования   Маркетинг   JTBD
  ├─ Фичи                    ├─ Гипотезы   (было RTB)   ├─ Список
  ├─ Конкуренты              ├─ Разговоры               └─ Граф (общий + по сегментам)
  ├─ Люди                    └─ Инсайты
  └─ Департаменты

Представления (переключатель в шапке, ветка 2.0):
  /pm  ·  /cpo  ·  /public  ·  /marketing-hub  ·  /sales-hub
```

5 главных табов вместо прежнего плоского списка из 9 пунктов. На ветке `2.0` под «Продуктами» добавились «Люди» и «Департаменты», а рядом с поиском — переключатель представлений (`/pm`, `/cpo`, `/public`, `/marketing-hub`, `/sales-hub`); это **не** граница доступа, а просто набор ссылок. Меню раскрывается постепенно: пока в разделе нет ни одной записи, его пункт скрыт, но маршрут, поиск и хоткеи работают всегда — как только запись появляется, пункт встаёт на место (переключатель «Показать все разделы» доступен всегда). У «Продуктов» и «Исследований» есть выпадающее под-меню (наведение/фокус), у JTBD — переключатель "Список"/"Граф" на самой странице раздела, а сам граф дополнительно переключается между общим представлением и графом конкретного сегмента (у каждого — своя независимая раскладка узлов). Конкуренты — под-пункт меню «Продукты», рядом с «Фичи» (маршрут `/competitors` не менялся, просто теперь виден в навигации). RTB переименован в "Маркетинг" в навигации и заголовках (маршрут `/rtb` → `/marketing`; Prisma-модель осталась `RTB`). В шапке есть поле поиска (`/search?q=`) по всем модулям. Отдельно от этой навигации — `/reports` (не в верхнем меню): матрица "Сегменты × JTBD" и очередь пробелов «Что делать дальше», аналитические страницы поверх уже собранных данных.

## Текущее состояние

Реализовано и работает:

- **11 контентных моделей 1.0**: Product, Research, Segment, JTBD (+граф последовательности, +персистентные позиции узлов по представлению), Hypothesis (+история статусов), Conversation, Competitor (+лог новостей), ProductResource, Feature, RTB, Insight — методологическое ядро JTBD → Feature → RTB собрано целиком. На ветке `2.0` к ним добавились Person, Department, RoadmapItem, Process/ProcessStep/ProcessEdge, ActionPlan, ProductTeamMember и раскладка холста продукта — всего 25 моделей в схеме.
- **Граф JTBD** (`/jtbd/graph`, React Flow): иерархия задач с перетаскиванием, связи "следует за", 4 типа задач (big/core/small/micro job) с цветовой легендой, инлайн-добавление узла прямо на канвасе. JTBD↔Сегмент — связь многие-ко-многим; у графа есть переключатель между общим представлением продукта и графом конкретного сегмента, у каждого представления — независимо сохраняемая раскладка узлов (кнопка «Автоматически расставить» пересчитывает только текущее представление).
- **Kanban гипотез** (`/hypotheses`): перетаскивание карточек между статусами, нативный HTML5 Drag and Drop.
- **Инлайн-редактирование** — клик по значению скалярного поля на любой из 12 детальных страниц (10 разделов 1.0 плюс `/people/[id]` и `/departments/[id]` на ветке `2.0`) превращает его в инпут на месте (без перехода на отдельную форму); поля-связи по-прежнему редактируются через полную форму.
- **Конкурент**: лог новостей/наблюдений (простой CRUD-подсписок) и доп. атрибуты (модель ценообразования, размер компании, дата последней проверки).
- **Фильтры фич** по JTBD и сегменту.
- **Фирменный красно-белый стиль** («Реестр» — сквозная нумерация записей + сигнальные цвета типов/статусов), карточная группировка на странице продукта и списках Конкурентов/Фич/Маркетинга/Инсайтов (группировка по продукту).
- **5-табовая навигация** с выпадающими под-меню (Продукты → Фичи, Конкуренты; Исследования → Гипотезы, Разговоры, Инсайты) и переключателем "Список"/"Граф" на JTBD.
- **Дашборд** (`/`): компактная навигационная плашка по всем разделам + настраиваемая сетка виджетов (сводка пробелов, покрытие JTBD, воронка гипотез, спарклайн частоты исследований, недавно просмотренное, закреплённое, лента активности) — можно скрывать и перетаскивать через панель «Настроить дашборд», раскладка сохраняется в браузере.
- **Инсайты** (`/insights`): атомарные цитаты и выводы из исследований/разговоров с привязкой к сегменту и/или JTBD — отдельно от полного транскрипта.
- **Отчёты** (`/reports`): матрица "Сегменты × JTBD" (доля JTBD, подтверждённых исследованиями, по сегментам и категориям, с корректным учётом многосегментных JTBD) и очередь пробелов «Что делать дальше» (сегменты без задач, продукты без свежих исследований, зависшие гипотезы, неподтверждённые JTBD — в порядке от самого блокирующего, с кнопкой нужного действия у каждой строки).
- **Глобальный поиск** (`/search?q=`): по 10 моделям сразу (все, кроме `ProductResource` и моделей 2.0 — `Person` и остальные в него не заведены), поле в шапке; обычный `contains`, без полнотекстового движка.
- **Массовый ввод и импорт** (ветка `2.0`): «Добавить списком» (одна запись на строку, до 200 строк), «Импорт CSV» с ручным сопоставлением колонок, «Взять заготовку» (3 отраслевых набора связанных сегментов/JTBD/гипотез, только пока продукт пустой), «Инбокс» (`/inbox` — вставленный текст режется по строкам, тип каждой строки выбирает человек) и быстрый захват по `c`/`⌘K` из любого места. Разбор везде механический, без ИИ.
- **Холст продукта** (`/products/[id]/canvas`, ветка `2.0`): цепочка сегмент → JTBD → гипотеза на одной поверхности React Flow, с созданием узла двойным кликом и связыванием перетаскиванием; узлы без нужной связи обводятся пунктиром с объяснением, чего не хватает.
- **Ролевые представления** (ветка `2.0`): `/pm` (роадмап списком и Гантом, команда, процессы, экшн-планы), `/cpo` (все продукты, пересечения, кросс-продуктовый Гант), `/public` (единственный сессионно-независимый маршрут, собран по белому списку полей), `/marketing-hub`, `/sales-hub`.
- **Тенант-guard на мутациях** (ветка `2.0`): `lib/ownership.ts` — единая проверка владельца по 21 модели, включая те, у которых нет своего `userId` и защита держится на цепочке связей.
- **Мастер настройки нового продукта** (`/products/[id]/onboarding/*`): необязательный выбор при создании продукта («Создать» vs «Создать и настроить →»), 6 шагов (Сегменты → JTBD → Исследования/Разговоры/Инсайты → Гипотезы → Конкуренты → Фичи и RTB) + страница-рекап, с возможностью пропустить в любой момент.
- **Мелкие удобства**: закреплённые записи, дублирование записи, CSV-экспорт, копирование ссылки, версия для печати, лента активности, клавиатурные сокращения, тёмная тема, обучающие пустые состояния и диалог удаления, показывающий, сколько зависимых записей уйдёт с каскадом.
- **Демо-данные**: полностью заполненный продукт «Рутокен CLM» на основе реального сейл-кита.

Осознанно не реализовано на этом этапе (решения продакт-менеджера, не пробелы) и что дальше — см. [`plans/backlog.md`](./plans/backlog.md). Найденные при финальном 1.0-ретесте UI-улучшения (не баги) — [`plans/ui-improvement-plan.md`](./plans/ui-improvement-plan.md). Что сделано на ветке `2.0` и почему именно так — `plans/platform-views-plan.md`, `plans/2.0-ux-improvement-plan.md`, `plans/2.0-visual-upgrade-plan.md`, `plans/2.0-product-leap-plan.md`, `plans/2.0-hardening-plan.md`.
