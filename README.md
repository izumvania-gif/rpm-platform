# RPM Platform

Платформа для product discovery: репозиторий клиентских исследований, сегменты, JTBD (с иерархией и визуальным графом), гипотезы, CustDev-разговоры и слой позиционирования продукта (конкуренты, фичи, RTB).

> **Ребрендинг:** продукт переименован из **ECHO** в **RPM Platform** (имя репозитория `rpm-platform` уже ему соответствовало) — переименование применено по всему UI и коду. Единственное намеренное исключение — [`ECHO_functional_requirements.md`](./ECHO_functional_requirements.md), архивный спек-документ под историческим именем. Остальной план развития — в [`plans/growth-plan.md`](./plans/growth-plan.md).

## Технологический стек

- **Frontend:** Next.js 14 (App Router), React 18, TypeScript — fullstack-монолит, отдельного backend-сервиса нет
- **Styling:** TailwindCSS, shadcn/ui, фирменный красно-белый стиль ("Rutoken corporate") через CSS-переменные, поддержка тёмной темы
- **Database:** PostgreSQL 15+ через Prisma ORM (`prisma db push`, без миграций в dev-режиме)
- **Authentication:** NextAuth.js (Credentials provider), сейчас все данные фактически ведутся под одним захардкоженным пользователем — многопользовательский режим не задействован
- **Валидация:** Zod
- **Граф JTBD:** `@xyflow/react` (React Flow) — единственная нестандартная зависимость UI

`@tanstack/react-query` и `react-hook-form` установлены в `package.json`, но нигде не используются — формы построены на нативных Server Actions + `useTransition`, без клиентского стейт-менеджера. Не полагайтесь на эти пакеты как на часть архитектуры.

## Начало работы

### Предварительные требования

- Node.js 20+
- PostgreSQL 15+
- npm

### Установка

1. Клонируйте репозиторий:

```bash
git clone <repository-url>
cd rpm-platform
```

2. Установите зависимости:

```bash
npm install
```

3. Настройте переменные окружения:

```bash
cp .env.example .env.local
```

Отредактируйте `.env.local` и укажите правильные данные для подключения к PostgreSQL.

4. Инициализируйте базу данных и загрузите демо-данные:

```bash
npm run db:push
npm run db:seed
```

5. Запустите сервер разработки:

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) в браузере.

## Доступные команды

- `npm run dev` — запуск сервера разработки
- `npm run build` — сборка для production
- `npm run start` — запуск production сервера
- `npm run lint` — проверка кода линтером
- `npm run format` — форматирование кода с помощью Prettier
- `npm run db:push` — синхронизация схемы Prisma с БД (без файла миграции — используется в dev)
- `npm run db:migrate` — создание и применение миграции
- `npm run db:generate` — генерация Prisma Client
- `npm run db:studio` — Prisma Studio GUI

Автотестов пока нет — осознанное решение на текущем этапе (см. «Планы» ниже).

## Структура продукта

```
Продукты   Сегменты   Исследования   Маркетинг   JTBD
  │                       │           (было RTB)   │
  ├─ Конкуренты*          ├─ Гипотезы               ├─ Список
  └─ Фичи                 ├─ Разговоры               └─ Граф
                          └─ Инсайты

* Конкуренты не в выпадающем меню — доступны только со страницы продукта.
```

5 главных табов вместо прежнего плоского списка из 9 пунктов. У «Продуктов» и «Исследований» есть выпадающее под-меню (наведение/фокус), у JTBD — переключатель "Список"/"Граф" на самой странице раздела. Конкуренты вообще не в верхнем меню — единственная точка входа теперь секция "Конкуренты" на странице конкретного продукта; маршрут `/competitors` при этом не удалён, просто не рекламируется. RTB переименован в "Маркетинг" в навигации и заголовках (маршрут `/rtb` → `/marketing`; Prisma-модель осталась `RTB`). В шапке есть поле поиска (`/search?q=`) по всем модулям. Отдельно от этой навигации — `/reports` (не в верхнем меню): матрица "Сегменты × JTBD" и дашборд пробелов, аналитические read-only страницы поверх уже собранных данных. Подробности и обоснование каждого решения — [`plans/growth-plan.md`](./plans/growth-plan.md), раздел «Информационная архитектура и навигация».

## Текущее состояние

Реализовано и работает:

- **11 моделей данных**: Product, Research, Segment, JTBD (+граф последовательности), Hypothesis (+история статусов), Conversation, Competitor, ProductResource, Feature, RTB, Insight — методологическое ядро JTBD → Feature → RTB собрано целиком.
- **Граф JTBD** (`/jtbd/graph`, React Flow): иерархия задач с перетаскиванием, связи "следует за", 4 типа задач (big/core/small/micro job) с цветовой легендой, инлайн-добавление узла прямо на канвасе.
- **Kanban гипотез** (`/hypotheses`): перетаскивание карточек между статусами, нативный HTML5 Drag and Drop.
- **Фильтры фич** по JTBD и сегменту.
- **Фирменный красно-белый стиль**, светлая и тёмная тема, карточная группировка на странице продукта, дашборде и списках Конкурентов/Фич/Маркетинга/Инсайтов (группировка по продукту).
- **5-табовая навигация** с выпадающими под-меню (Продукты → Фичи; Исследования → Гипотезы, Разговоры, Инсайты) и переключателем "Список"/"Граф" на JTBD.
- **Инсайты** (`/insights`): атомарные цитаты и выводы из исследований/разговоров с привязкой к сегменту и/или JTBD — отдельно от полного транскрипта.
- **Отчёты** (`/reports`): матрица "Сегменты × JTBD" (доля JTBD, подтверждённых исследованиями, по сегментам и категориям) и дашборд пробелов (неподтверждённые JTBD, сегменты без задач, зависшие гипотезы, продукты без свежих исследований).
- **Глобальный поиск** (`/search?q=`): по всем 11 моделям сразу, поле в шапке.
- **Мастер настройки нового продукта** (`/products/[id]/onboarding/*`): необязательный выбор при создании продукта («Создать» vs «Создать и настроить →»), 6 шагов (Сегменты → JTBD → Исследования/Разговоры/Инсайты → Гипотезы → Конкуренты → Фичи и RTB) + страница-рекап, с возможностью пропустить в любой момент.
- **Мелкие удобства**: закреплённые записи, дублирование записи, CSV-экспорт, копирование ссылки, версия для печати, лента активности, клавиатурные сокращения.
- **Демо-данные**: полностью заполненный продукт «Рутокен CLM» на основе реального сейл-кита.

Осознанно не реализовано на этом этапе (решения продакт-менеджера, не пробелы): дополнительная валидация целостности данных (например, JTBD-иерархия ↔ тип задачи, защита графа последовательности от циклов) и автотесты/CI — платформа намеренно остаётся гибкой, а тестирование — ручным, пока не назрела необходимость.

Полный, детальный снимок текущего состояния (со схемами и техническими решениями) — [`plans/growth-plan.md`](./plans/growth-plan.md), часть 1 «Текущее состояние».
