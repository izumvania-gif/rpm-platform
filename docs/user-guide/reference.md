# Справочник по разделам

Что находится в каждом разделе платформы, какие поля есть и как разделы связаны друг с другом. Для пошаговых сценариев — см. [scenarios.md](./scenarios.md).

Все разделы, кроме «Отчётов», есть в верхнем меню (`Продукты`, `Сегменты`, `Исследования`, `Маркетинг`, `JTBD`; под «Продукты» — «Фичи» и «Конкуренты», под «Исследования» — «Гипотезы» и «Разговоры»). «Инсайты» — тоже под «Исследования». «Отчёты» — по ссылке с дашборда, в верхнем меню их нет.

## Продукты

Верхнеуровневая сущность — всё остальное привязано к продукту. Поля: название, slug (латиницей, для читаемых ссылок), стадия (`Идея` / `MVP` / `Рост` / `Масштабирование`), описание.

Страница продукта — центральный хаб: две группы разделов («Исследование клиентов» и «Позиционирование»), в каждой — карточка на модель с количеством записей и кнопкой быстрого добавления. Плюс отдельный блок «Ресурсы» (sales-kit, документация для разработчиков, ссылки на Confluence/Jira — просто заголовок + ссылка + тип, без предпросмотра содержимого).

Удаление продукта каскадно удаляет все связанные записи — сегменты, JTBD, гипотезы, разговоры, инсайты, конкурентов, фичи, RTB. Подтверждение запрашивается явно.

## Сегменты

Кто ваши клиенты. Поля: название, доля аудитории в процентах (необязательно), цвет (для визуальных меток), описание, теги.

Связаны с: JTBD, Гипотезами, Разговорами, Инсайтами — сегмент можно привязать к любой из этих записей, необязательно ко всем сразу.

## Исследования

Формальные исследовательские активности — не разговоры, а именно исследования как процесс (опрос, юзабилити-тест, desk-research и т.д.). Поля: название, описание, дата, статус (`В работе` / `Завершено`), тип (`Качественное`, `Опрос`, `Аналитика`, `Desk Research`, `Ручное`, `Количественное`, `Юзабилити-тестирование`), теги.

Каждое исследование получает сквозной номер (`#31`, `#32`...) — не редактируется, присваивается автоматически по порядку создания. Используйте этот номер, когда ссылаетесь на исследование в переписке или презентации — короче, чем полное название.

Связано с: JTBD, Гипотезами, Разговорами, Инсайтами — все они могут ссылаться на конкретное исследование как на источник.

## JTBD (Jobs To Be Done)

Задачи клиентов. Поля: формулировка (по схеме «Когда …, я хочу …, чтобы …»), категория (свободный текст с автодополнением уже использованных категорий — не enum, можно вводить новые), тип по масштабу (`Большая задача` / `Основная задача` / `Малая задача` / `Микрозадача`), описание, флаг «Подтверждено исследованием», теги.

Есть два представления:
- **Список** (`/jtbd`) — плоский список, группировка по категориям.
- **Граф** (`/jtbd/graph`) — канвас с иерархией (родитель → потомок, drag узла на узел) и последовательностью (сплошная стрелка, отдельная от иерархии — «задача A предшествует задаче B»). Цвет узла = тип по масштабу, легенда на канвасе. Переключатель вверху канваса даёт выбор между общим графом продукта и графом конкретного сегмента — у каждого представления своя, независимо сохраняемая раскладка узлов (перетащили — запомнилось; кнопка «Автоматически расставить» пересчитывает заново только текущее представление).

Связано с: Сегментом (многие-ко-многим — один JTBD может относиться сразу к нескольким сегментам, у каждого будет свой граф) и Исследованием (опционально, по одному на JTBD), а также Гипотезами, Фичами, Инсайтами (многие могут ссылаться на одну задачу).

## Гипотезы

Проверяемые предположения. Поля: формулировка (по схеме «Если …, то …»), статус (`Черновик` → `На проверке` → `Подтверждена` / `Опровергнута`), приоритет (число, необязательно), теги.

Единственный раздел с kanban-представлением вместо списка — карточки перетаскиваются между колонками статуса мышью. Полная история переходов статуса сохраняется и видна на детальной странице.

Связано с: JTBD, Сегментом, Исследованием (опционально, по одному на гипотезу) — так гипотеза объясняет, для какого клиента и какую задачу вы проверяете.

## Разговоры

CustDev-звонки и встречи. Поля: название, дата, транскрипт (полный текст, необязательно), теги.

Связано с: Сегментом и Исследованием (опционально) — а также с Инсайтами: один разговор обычно порождает несколько инсайтов.

## Инсайты

Атомарные цитаты и выводы — отдельно от полного транскрипта разговора. Поля: текст, теги.

Единственная модель, у которой может быть до четырёх опциональных связей одновременно: Сегмент, JTBD, Исследование, Разговор. Заполняйте только применимое — необязательно указывать все четыре.

## Конкуренты

Поля: название, ссылка, позиционирование (текстом — в чём сила, в чём уязвимость), список фич конкурента (простой текстовый список, не связанные записи), модель ценообразования (текст), размер компании/стадия (текст), дата последней проверки информации.

Плюс отдельный под-список **«Новости и наблюдения»** прямо на карточке конкурента — заголовок, необязательная ссылка, дата, заметка. Простой журнал: добавляется и удаляется прямо там же, без перехода на отдельную страницу. Это ручной лог, а не автоматический мониторинг — платформа не ищет новости сама, только хранит то, что вы туда занесли.

Не привязаны ни к чему, кроме продукта — нет связи с JTBD или сегментами напрямую.

## Фичи

Как продукт закрывает JTBD. Поля: название, описание.

Связано с: JTBD (многие-ко-многим, чекбоксами в форме — какие задачи клиента закрывает эта фича) и RTB (многие-ко-многим — какие обещания на неё опираются).

## Маркетинг (RTB — Reasons To Believe)

Маркетинговые обещания, которые опираются на конкретные фичи. Поля: формулировка обещания.

Связано с: Фичами (многие-ко-многим, чекбоксами — на каких фичах основано обещание). В интерфейсе раздел называется «Маркетинг», но в базе данных и коде это модель `RTB` — если ищете в коде, ищите по этому имени.

## Отчёты

Не отдельная CRUD-модель, а два read-only представления поверх уже собранных данных:

- **Матрица Сегменты × JTBD** (`/reports/segments-jtbd`) — по продукту, строки — сегменты, столбцы — категории JTBD, ячейка — доля подтверждённых исследованием задач.
- **Дашборд пробелов** (`/reports/gaps`) — четыре живых запроса: JTBD без подтверждения, сегменты без единого JTBD, гипотезы старше 14 дней в «Черновике», продукты без исследований за 90 дней.

## Мелкие удобства, доступные почти везде

- **Инлайн-редактирование** — клик по значению скалярного поля (название, описание, дата, теги, статус/тип/стадия и т.п.) на любой из 10 детальных страниц превращает его в инпут на месте, без перехода в форму редактирования. Поля-связи (сегменты, привязанные фичи и т.д.) так не редактируются — только через полную форму. Подробнее — [scenarios.md](./scenarios.md), сценарий 9.
- **Закреплённое** (звёздочка на карточке) — попадает в блок «Закреплённое» на дашборде. Доступно на всех моделях, кроме Продуктов.
- **Дублирование записи** — кнопка «Дублировать» на детальной странице, открывает форму создания с предзаполненными полями.
- **Экспорт CSV** — кнопка на странице списка, выгружает то, что видно на экране (с учётом фильтров).
- **Скопировать ссылку** — кнопка рядом с заголовком детальной страницы.
- **Версия для печати** — только на странице продукта; печатная раскладка скрывает навигацию и кнопки действий.
- **Теги** — свободный текст через запятую, есть у Исследований, Сегментов, JTBD, Гипотез, Разговоров и Инсайтов (у Конкурентов, Фич, RTB и Продуктов тегов нет), показываются как бейджи в списках.
- **Сортировка и фильтры** — на страницах списков (не на канвасе графа JTBD и не на kanban-доске гипотез, у них своя логика).
