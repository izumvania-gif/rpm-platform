# Ключевые сценарии

Пошаговые сценарии для конкретных рабочих ситуаций. Общий обзор — в [README.md](./README.md), справочник по полям — в [reference.md](./reference.md).

## 1. Быстрый старт нового продукта (мастер онбординга)

**Когда использовать:** продукт совсем новый, данных о клиентах и задачах пока нет или есть только в голове/в другом документе.

1. «Продукты» → «Новый продукт», заполните название, стадию (обычно «Идея»), описание.
2. Нажмите **«Создать и настроить →»** (не просто «Создать» — вторая кнопка запускает мастер).
3. Мастер проведёт по 6 шагам, каждый — с вопросом, а не голой формой:
   - **Сегменты** — «Кто ваши клиенты?»
   - **JTBD** — «Какие задачи вы для них решаете?» (с привязкой к сегменту и масштабом задачи — большая/основная/малая/микро)
   - **Исследования / Разговоры / Инсайты** — «Откуда вы это знаете?», три под-секции на одной странице
   - **Гипотезы** — «Что вы предполагаете?»
   - **Конкуренты** — «С кем вы конкурируете?»
   - **Фичи и RTB** — «Что вы предлагаете и почему это должны купить?»
4. На каждом шаге можно добавить сколько угодно записей — форма не закрывается после первой, список пополняется на той же странице. Шаг можно пропустить кнопкой «Далее →», если добавить нечего.
5. В любой момент можно нажать «Пропустить настройку →» и уйти сразу на страницу продукта — прогресс мастера не теряется, к недостающим шагам можно вернуться позже вручную через обычные разделы.
6. Последний экран — рекап: сколько записей в каждом из 9 разделов, с прямыми ссылками «заполнить»/«изменить».

**Важно знать:** списки внутри мастера — только на добавление. Если добавили что-то по ошибке, удалить это в мастере нельзя — открываете обычный раздел (например, «Сегменты») и удаляете запись оттуда как обычно.

## 2. Ведение уже существующего продукта: сегмент → JTBD → гипотеза

**Когда использовать:** продукт уже заведён, вы получили новую информацию по конкретному сегменту (например, после серии интервью) и хотите зафиксировать выводы без прохождения всего мастера заново.

1. Откройте продукт → секция «Исследование клиентов» → «Добавить сегмент», если сегмента ещё нет. Укажите название, долю аудитории (если знаете), теги.
2. «Добавить JTBD» — сформулируйте задачу по схеме «Когда …, я хочу …, чтобы …», привяжите к только что созданному сегменту (чекбоксом — одна задача может относиться сразу к нескольким сегментам, если она у них общая), укажите категорию (свободный текст с автодополнением уже существующих категорий — не бойтесь опечататься в новой, платформа не ограничивает список) и масштаб (большая/основная/малая/микро задача).
3. Если задача уже подтверждена исследованием — откройте карточку JTBD, нажмите «Редактировать» и отметьте «Подтверждено исследованием» (это поле-чекбокс — на карточке напрямую не редактируется, только через форму). Это поле напрямую влияет на «Пробелы: что делать дальше» и матрицу «Сегменты × JTBD».
4. «Добавить гипотезу» на странице продукта (или через раздел «Гипотезы» → «Новая гипотеза») — сформулируйте по схеме «Если …, то …», привяжите к JTBD и сегменту. Гипотеза стартует в статусе «Черновик».

## 3. Обработка CustDev-разговора: разговор → инсайты → привязка

**Когда использовать:** только что закончился звонок или встреча с клиентом.

1. «Исследования → Разговоры» → «Новый разговор». Название, дата, привязка к сегменту и (если разговор был частью формального исследования) к исследованию. При желании — вставьте транскрипт целиком в соответствующее поле.
2. Не останавливайтесь на транскрипте — выделите из разговора 2–4 атомарные мысли и заведите их как **Инсайты** («Исследования → Инсайты» → «Новый инсайт»). Каждый инсайт — либо прямая цитата, либо ваш вывод, привязанный к сегменту, JTBD, исследованию и/или разговору (заполняйте только то, что применимо — необязательно всё сразу).
3. Зачем разделять транскрипт и инсайты: через месяц вы не будете перечитывать часовую запись целиком, чтобы найти одну фразу — вы найдёте её как отдельный инсайт с прямой ссылкой на источник.
4. Если разговор подтвердил или опроверг существующую гипотезу — зайдите в карточку гипотезы и переключите статус.

## 4. Работа с гипотезами: от идеи до подтверждения

**Когда использовать:** постоянно, это ваш еженедельный ритуал.

1. «Гипотезы» — вы на kanban-доске с четырьмя колонками: Черновик, На проверке, Подтверждена, Опровергнута.
2. Новая гипотеза всегда стартует в «Черновике» (создать можно прямо с доски кнопкой «Новая гипотеза», или из карточки продукта).
3. Как только начали проверять гипотезу исследованием — перетащите карточку в «На проверке» (drag-and-drop мышью).
4. По итогам исследования — перетащите в «Подтверждена» или «Опровергнута». История переходов сохраняется на карточке гипотезы (видна на детальной странице, с датами каждого перехода).
5. Звёздочка на карточке — закрепить гипотезу, чтобы она попала в блок «Закреплённое» на дашборде. Полезно для 3–5 гипотез, которые вы прямо сейчас обсуждаете со стейкхолдерами.
6. Если гипотеза «зависла» в черновике больше двух недель без движения — она сама всплывёт в «Отчёты → Пробелы: что делать дальше», не нужно помнить о ней вручную, и оттуда же её можно отправить «На проверку» одной кнопкой.

## 5. Построение графа JTBD: иерархия и последовательность

**Когда использовать:** когда задач набралось много и хочется увидеть, как они связаны между собой, а не листать плоский список.

1. «JTBD» → переключатель «Граф» (или прямая ссылка `/jtbd/graph`).
2. Каждый узел — задача, цвет — тип по масштабу (фиолетовый — большая, красный — основная, синий — малая, серый — микро; легенда всегда видна в левом нижнем углу канваса).
3. **Переключатель «Общий граф» / конкретный сегмент** сверху канваса — у каждого представления своя независимая раскладка узлов: как расставите задачи на общем графе, никак не повлияет на их позиции в графе отдельного сегмента, и наоборот. Узел виден в графе сегмента только если JTBD к этому сегменту привязан; связи к узлам вне текущего представления не рисуются.
4. **Перетащите один узел на другой**, чтобы сделать его дочерним (появится пунктирная связь «родитель → потомок»). Перетаскивание в пустое место канваса просто меняет и сохраняет позицию узла — расстановка переживает перезагрузку страницы и не сбрасывается при следующем редактировании графа.
5. **Потяните от края узла к другому узлу**, чтобы задать последовательность («задача A предшествует задаче B» — сплошная синяя стрелка). Это отдельный тип связи от иерархии — задачи могут быть на одном уровне иерархии, но идти друг за другом по времени.
6. Выделите связь и нажмите Delete, чтобы её убрать.
7. Кнопка «+ Добавить JTBD» прямо на канвасе — создаёт новый узел без перехода на отдельную страницу; если вы в графе конкретного сегмента, новая задача сразу привязывается к этому сегменту.
8. Кнопка «Автоматически расставить» — пересчитывает позиции всех узлов текущего представления по иерархии заново. Полезно, когда ручная раскладка запуталась и проще начать с чистого листа, чем распутывать вручную — затрагивает только то представление, в котором вы сейчас находитесь.
9. Клик по узлу открывает полную карточку JTBD (описание, привязанные гипотезы, фичи, инсайты).
10. Фильтр по категории сверху канваса — полезен, когда задач становится больше 15–20 и граф превращается в кашу.

## 6. Конкурентный анализ и позиционирование: Конкуренты → Фичи → RTB

**Когда использовать:** готовите позиционирование продукта или сравнительную презентацию.

1. Раздел «Конкуренты» — под-пункт меню «Продукты» (рядом с «Фичи»), либо со страницы конкретного продукта. «Добавить конкурента»: имя, ссылка, поле «Позиционирование» (в чём их сила, в чём уязвимость — коротко, тезисно), список их фич, а также модель ценообразования, размер компании/стадия и дата последней проверки информации. Появилась новость о конкуренте — не переписывайте позиционирование, а добавьте запись в лог «Новости и наблюдения» на его карточке (заголовок, ссылка, дата, заметка) — так сохраняется история наблюдений, а не только текущий снимок.
2. «Фичи» → «Новая фича» — назовите фичу и отметьте чекбоксами, какие JTBD она закрывает. Без этой привязки фича — просто пункт в списке; с привязкой — видно, решает ли она реальную задачу клиента или существует «просто потому что конкурент так сделал».
3. «Маркетинг» (это и есть RTB — Reasons To Believe) → «Новый RTB» — сформулируйте обещание клиенту и привяжите чекбоксами к фичам, на которых оно основано. Если для обещания нет ни одной фичи — вы сразу это увидите по пустому списку связей, и это сигнал, что RTB голословный.
4. На детальной странице фичи видно, какие JTBD она закрывает (с цветной точкой типа задачи у каждой) и какие RTB на неё ссылаются — обратная связь в обе стороны.

## 7. Еженедельный ревью: отчёт о пробелах и матрица Сегменты × JTBD

**Когда использовать:** раз в 1–2 недели, как гигиенический ритуал, отдельно от текущей работы по конкретным продуктам.

1. «Отчёты» (ссылка с дашборда: «Отчёты: матрица Сегменты × JTBD, пробелы →») → «Пробелы: что делать дальше».
2. Четыре группы, каждая — прямой запрос по данным, а не ручной чек-лист. Идут не в произвольном порядке, а от самого блокирующего к наименее срочному, и группа без единой задачи не показывается вовсе:
   1. **Сегменты без единого JTBD** → «Добавить JTBD». Самое блокирующее: пока у сегмента нет задач клиента, ниже по цепочке не может появиться ни гипотез, ни фич. Кнопка открывает форму с уже подставленными продуктом и сегментом.
   2. **Продукты без исследований за последние 90 дней** → «Запланировать исследование» (продукт подставлен). Остановилась сама практика, а не отдельная запись.
   3. **Гипотезы, зависшие в «Черновике» дольше 14 дней** → «На проверку» переводит гипотезу в следующий статус прямо из очереди, не открывая карточку; «Открыть» ведёт в карточку, если нужно разобраться.
   4. **JTBD без подтверждения исследованием** → «Привязать исследование». Кнопки «подтвердить одним кликом» здесь намеренно нет: подтверждение означает «за задачей стоит исследование», и проставлять его из отчёта означало бы обесценить ровно ту метрику, ради которой этот пробел и считается.
3. Когда очередь пуста, страница так и говорит — это нормальное состояние, а не ошибка.
4. «Отчёты» → «Матрица Сегменты × JTBD» — выберите продукт вверху, читайте таблицу: строки — сегменты, столбцы — категории JTBD, ячейка — «подтверждено / всего» с заливкой по доле подтверждения. Пустая ячейка — у сегмента просто нет задач в этой категории (не то же самое, что 0 из N).
5. Используйте матрицу как чек-лист перед защитой роадмапа: если у ключевого сегмента вся строка бледная — у вас недостаточно данных, чтобы уверенно на него ссылаться.

## 8. Поиск нужной записи и «недавно просмотренное»

**Когда использовать:** вы помните фразу или тему, но не помните, в каком разделе и продукте это искать.

1. Поле поиска в шапке (доступно с любой страницы, кроме мобильной ширины экрана, где оно скрыто) — введите запрос, Enter.
2. Результаты сгруппированы по типу записи (Продукты, Исследования, Сегменты, JTBD, Гипотезы, Разговоры, Конкуренты, Фичи, Маркетинг, Инсайты) с количеством в каждой группе — до 20 записей на тип.
3. Поиск ищет по подстроке без учёта регистра в ключевых текстовых полях каждой модели — это не полнотекстовый поиск с ранжированием, а прямой запрос к базе, поэтому лучше искать точные фразы, а не общие слова.
4. Если знаете, что запись открывали недавно, но не через поиск — на дашборде есть виджет «Недавно просмотренное» (хранится локально в браузере, не в базе — если открыть платформу с другого устройства, истории не будет).

## 9. Быстрая правка одного поля прямо на карточке

**Когда использовать:** нужно поправить название, описание, дату, тег или статус — и только это одно поле, без похода в форму редактирования.

1. Откройте любую детальную страницу (например, JTBD или Конкурента) и кликните по значению нужного поля — название, описание, дата, теги, статус/тип/стадия (там, где это select), у Конкурента — ещё и модель ценообразования, размер компании, дата проверки.
2. Значение превращается в поле ввода на месте. Для короткого текста и чисел — `Enter` сохраняет, `Esc` отменяет. Для текстовых областей — клик в любое другое место сохраняет, `Esc` отменяет. Для даты и select — сохранение происходит сразу при выборе.
3. Если поле обязательно (например, «Название») и вы очистили его до пустой строки — платформа не даст сохранить, покажет ошибку прямо под полем и оставит поле открытым, пока не введёте корректное значение.
4. Пустое необязательное поле показывает приглушённую подсказку «+ добавить …» вместо пустого места — кликните так же, как по заполненному.
5. Поля-связи (какие сегменты у JTBD, какие фичи привязаны и т.д.) так не редактируются — для них по-прежнему нужна полная форма («Редактировать»), там уже есть чекбоксы/мультивыбор.
