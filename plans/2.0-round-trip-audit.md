# Аудит хождений туда-обратно при вводе данных

Замер на живом приложении (dev-сборка, демо-набор), а не по памяти. Вопрос:
где ещё остались лишние переходы, и что из этого уже закрыла модалка быстрого
захвата.

## Что модалка закрыла на самом деле

`QuickAddButton` встречается ровно в одном месте — `components/products/module-card.tsx`.
То есть **только карточки разделов на странице продукта**. Замер:

| Путь                                              | Переходов на 2 записи |
| ------------------------------------------------- | --------------------- |
| Страница продукта → «+» на карточке → модалка      | **0**                 |
| Список `/jtbd` → «Новый JTBD» → форма → сохранение | **6**                 |

Разница не только в числе. После сохранения из формы `createJtbd` делает
`redirect('/jtbd/<id>')` — то есть выбрасывает на **карточку созданной
записи**, а не обратно в список, откуда пришли. Чтобы завести вторую задачу,
надо вернуться самому. То же у `createSegment`, `createFeature`, `createRTB`,
`createCompetitor`, `createInsight`.

Итог: 11 страниц-списков (`/jtbd`, `/segments`, `/features`, `/hypotheses`,
`/marketing`, `/insights`, `/competitors`, `/conversations`, `/research`,
`/people`, `/departments`) до сих пор ведут в полную форму. Для 7 из них тип
записи модалка уже умеет создавать — просто кнопки там нет.

## Найденный баг: кнопка «Создать» молча не работала

Воспроизводится так: открыть `/jtbd/new` **без** `?productId=` — ровно то, куда
ведёт «Новый JTBD» с любой страницы-списка, — заполнить формулировку и
категорию, нажать «Создать». Не происходит **ничего**: ни перехода, ни
сообщения, ни подсветки поля. Кнопка выглядит сломанной.

Причина в `components/ui/select.tsx`. Radix-селект дублирует значение в
настоящий `<select>`, чтобы `FormData` в Server Action работал как раньше. Этот
дубль был помечен `hidden`. Браузер отказывается отправлять форму, пока
`required`-поле пустое, но показать своё сообщение на неотображаемом элементе
не может — он пишет в консоль

```
An invalid form control with name='productId' is not focusable.
```

и на этом останавливается. Пользователь не видит ничего.

Задето каждое поле `required` в `Select`, то есть «Продукт» во всех формах
создания плюс тип/статус там, где они обязательны.

**Исправлено** в этом же коммите: дубль больше не `hidden`, а вынесен из потока
(`absolute h-px w-px opacity-0`) — остаётся невидимым и вне дерева доступности,
но браузер может поставить на него фокус и показать подсказку. Плюс
`setCustomValidity('Выберите значение из списка')`, чтобы сообщение было
по-русски независимо от локали браузера, и снимался, как только значение
выбрано. Регрессия закрыта `e2e/required-select.spec.ts`.

## Главный оставшийся разрыв: поля-связи без «создать на месте»

Из 18 полей-связей в формах (не считая фильтров) escape hatch есть у **четырёх
— и это одно и то же поле**, сегмент (`InlineCreateSegment`):

| Форма             | Поле-связь                                  | Создать на месте |
| ----------------- | ------------------------------------------- | ---------------- |
| jtbd-form         | Сегменты                                    | ✅               |
| jtbd-form         | Исследование                                | ❌               |
| hypothesis-form   | Сегмент                                     | ✅               |
| hypothesis-form   | JTBD, Исследование                          | ❌               |
| insight-form      | Сегмент                                     | ✅               |
| insight-form      | JTBD, Исследование, Разговор                | ❌               |
| conversation-form | Сегмент                                     | ✅               |
| conversation-form | Исследование                                | ❌               |
| feature-form      | JTBD, RTB                                   | ❌               |
| rtb-form          | Фичи                                        | ❌               |
| roadmap-item-form | Ответственный, Фича, JTBD                   | ❌               |
| action-plan-form  | Ответственный, Шаг процесса                 | ❌               |
| product-form      | Ответственный, Департамент                  | ❌               |

Это хуже, чем лишний переход: форма уже заполнена, а нужной записи в списке
нет. Уйти и создать её — значит потерять набранное, потому что форма
серверная и черновик нигде не хранится. Наглядно видно на скриншоте формы
JTBD: «Сегменты» с ссылкой «+ Новый сегмент» и рядом «Исследование» с голым
«Не указано».

Три поля повторяются чаще всего, и **у всех трёх нужный `createXQuick` уже
написан** — не хватает только общего UI:

| Поле                        | В скольких формах | Готовый экшен                  |
| --------------------------- | ----------------- | ------------------------------ |
| Исследование (`researchId`) | 4                 | `createResearchQuick`          |
| Ответственный (`ownerId`)   | 3                 | `createPersonAndAddToTeamQuick`|
| JTBD (`jtbdId`)             | 3                 | `createJtbdQuick`              |

`InlineCreateSegment` стоит обобщить до общего пикера с созданием на месте и
подключить к этим трём.

## Мелочи, замеченные попутно

- **`/segments/[id]` не умеет ничего добавлять.** На карточке сегмента видно
  его задачи, но завести ещё одну можно только через `/jtbd/new` с выбором
  сегмента там. У `/research/[id]` и `/conversations/[id]` инлайн-добавление
  инсайта есть (`QuickAddInsight`), у сегмента — нет.
- **«Ответственный: + назначить» на карточке продукта** — инлайн-селект по уже
  существующим людям. Если человека ещё нет, единственный путь — уйти на
  `/people/new`. То же у «Департамент».
- **Модалка не знает про Роадмап, Процессы, Департаменты и Людей.** Для роадмапа
  это неважно (на `/pm` своя инлайн-форма, а на диаграмме Ганта — лоток и
  планирование перетаскиванием), а вот человек нужен из трёх разных форм.

## Порядок, если браться

1. **Общий инлайн-пикер с созданием на месте** для исследования, человека и
   JTBD. Самая большая снятая боль: только он спасает уже набранную форму.
2. **«+» с модалкой на страницах-списках** — 7 типов из 11 модалка уже умеет,
   нужна только кнопка рядом с «Новый …».
3. **Возврат туда, откуда пришли, после создания** — `createX` мог бы принимать
   `redirectTo`, как уже делает `updateJtbd`.
4. **Кнопка добавления JTBD на карточке сегмента** — по образцу `QuickAddInsight`.
