# Архив

Историческая документация разработки — сохранена для контекста, но больше не поддерживается и не отражает текущее состояние продукта. Если вы ищете актуальную информацию, начните с:

- [`PROJECT_STATE.md`](../../PROJECT_STATE.md) — что сейчас реально построено, коротко.
- [`plans/backlog.md`](../backlog.md) — что осознанно отложено или не реализовано, на будущее.
- [`plans/ui-improvement-plan.md`](../ui-improvement-plan.md) — найденные при 1.0-ретесте возможности улучшить UI.
- [`plans/ai-implementation-plan.md`](../ai-implementation-plan.md) — черновой план подключения AI (анализ, не реализовано).
- [`README.md`](../../README.md) — установка, стек, структура репозитория.
- [`docs/user-guide/`](../../docs/user-guide/README.md) — руководство пользователя.

## Что здесь лежит и почему

- **`visual-redesign-plan.md`** — план визуального редизайна поверх уже построенного на 1.0 продукта: токены (палитра/типографика/тёмная тема), примитивы `components/ui/*` (Select на Radix и др.), «герои» (карточка узла JTBD-графа, дашборд как композиция, kanban-карточки, оверлей клавиатурных сокращений), проход по формам/спискам/`SiteNav`. Архивирован 8 августа 2026 — все 4 фазы сделаны, `PROJECT_STATE.md` подтверждает завершение. Источник §-нумерации, на которую ссылаются комментарии в коде (`components/ui/card.tsx`, `lib/labels.ts`, `lib/jtbd-job-types.ts`, `components/jtbd-graph/jtbd-node.tsx`, `components/shared/keyboard-shortcuts-overlay.tsx`, `e2e/helpers.ts`) — не переносите эти §-ссылки на другой файл при рефакторинге, они указывают именно сюда.
- **`dashboard-redesign-plan.md`** — редизайн `app/page.tsx` по запросу «дашборд перегружен, нужно меньше клога, больше actionable-данных и кастомизации»: общий слой метрик (`lib/dashboard-metrics.ts`), инфраструктура кастомизации виджетов (скрыть/показать/перетащить, раскладка в `localStorage`), четыре графических виджета (gaps-сводка, покрытие JTBD, воронка гипотез, спарклайн частоты исследований), замена крупных карточек-плиток на компактный `ModuleRail`. Архивирован 8 августа 2026 — все 4 фазы сделаны. Продолжение `visual-redesign-plan.md` (использует те же примитивы/токены), но целиком про композицию и содержание дашборда, не про стилизацию компонентов.
- **`growth-plan.md`** — основной живой план разработки на протяжении почти всей истории проекта (ребрендинг ECHO → RPM, навигация, визуальная идентичность «Реестр», граф JTBD, сегменты, конкуренты, инлайн-редактирование). Архивирован при подготовке релиза 1.0 (7 августа 2026) — весь описанный в нём план полностью реализован, обновлять его дальше уже некому. Технические решения и обоснования из него остаются ценными как исторический контекст (например, почему RTB называется «Маркетинг» в интерфейсе, но остался `RTB` в схеме) — при необходимости смотрите в файл напрямую.
- **`mvp-development-plan.md`, `mvp-quick-start-checklist.md`, `mvp-roadmap-visual.md`, `phase-0-completion.md`, `phase-0-summary.md`, `README.md`** (старый индекс) — самый ранний слой планирования, ещё под именем «ECHO Platform», Фазы 0–6 исходного MVP. Полностью выполнены и превзойдены задолго до 1.0 — оставлены как есть, не обновлялись очень давно, местами прямо противоречат текущему состоянию продукта (например, упоминают React Query и react-hook-form как часть архитектуры — оба пакета установлены, но нигде не используются).
- **`ECHO_functional_requirements.md`** — исходный функциональный спек продукта под первоначальным названием ECHO, включая P2/P3-функции (AI Chat, RAG, внешние агенты/MCP), ни одна из которых не реализована. Основа для `plans/backlog.md` — если планируете AI-функции, начните оттуда, а не с этого файла напрямую.
- **`QUICK_START.md`** — дублировал раздел «Начало работы» в README, но не обновлялся с самых ранних Фаз MVP (другое название продукта, устаревший статус фаз). README — источник истины для установки.
