# UI Improvement Plan

Составлено по итогам детального 1.0-ретеста (7 августа 2026) — систематического прохода по всем модулям, сценариям и взаимодействиям платформы (Playwright, dev-режим, полный CRUD на 10 моделях, граф JTBD, kanban гипотез, мастер онбординга, отчёты, поиск, клавиатурные сокращения, мобильная раскладка, тёмная тема, печать, CSV-экспорт). **Ретест не нашёл ни одного функционального бага** — все проверенные сценарии работают корректно, включая сквозной каскадный delete, drag-and-drop kanban, независимые графы по сегментам и т.д. Ниже — находки, требующие визуальной/UX доработки, а не багфикса, плюс что уже сделано в рамках этого же захода.

## Сделано в этом заходе (curated set, не исчерпывающе)

Согласовано с продакт-менеджером: реализовать точечный набор тултипов/подсказок для самых неочевидных мест, остальное — зафиксировать здесь на будущее.

- **`<InlineEditableField>`** (`components/shared/inline-editable-field.tsx`) — добавлен `title="Нажмите, чтобы отредактировать"` на кнопку просмотра. Применяется сразу на всех 10 детальных страницах моделей, где используется этот примитив — самое высокорычаговое из точечных добавлений.
- **Кнопка «Автоматически расставить»** на графе JTBD (`components/jtbd-graph/canvas.tsx`) — тултип объясняет, что пересчитывается только текущее представление (общий граф или граф сегмента), остальные не затрагиваются.
- **Переключатель графа** (`components/forms/jtbd-graph-filter-form.tsx`) — тултип поясняет, что у каждого представления своя независимая раскладка узлов.
- **Форма JTBD, мультивыбор сегментов** (`components/forms/jtbd-form.tsx`) — короткая подсказка под лейблом «Сегменты»: можно выбрать несколько, у каждого сегмента будет свой независимый граф.

## Приоритет 1 — стоит сделать в следующий заход

- **Дашборд: блок «Закреплённое» без ограничения длины.** На демо-данных (~15 закреплённых записей) блок растягивается на весь экран, визуально забивая соседний блок «Последняя активность» и создавая длинную стену текста, которую пользователь вряд ли долистает. Кандидаты: `max-height` + внутренний скролл, или лимит на N последних закреплённых + ссылка «показать все» на отдельную страницу/фильтр.

## Приоритет 2 — заметно, но не блокирует демо

- **Мобильная навигация (375px) не сворачивается в гамбургер** — пункты шапки остаются доступны горизонтальным скроллом, ничего не теряется, но выглядит не проработанным на мобильном экране. Актуально в первую очередь для демо с телефона/планшета; для десктоп-презентаций и custdev-звонков с шерингом экрана не критично.
- **Граф JTBD: невидимые узлы других сегментов.** Открывая граф конкретного сегмента, ребро к узлу из другого сегмента не рисуется вовсе — при малом числе JTBD это может озадачить («где связанная задача?»). Кандидат — полупрозрачный/неактивный узел вместо полного скрытия, чтобы сохранить контекст иерархии.
- **Категория JTBD — риск случайных дублей.** Поле свободный текст с автодополнением уже введённых категорий (осознанное решение — гибкость важнее строгости на этом этапе), но ничто не предупреждает, если новая категория близко похожа на существующую («Контроль сроков» vs «Контроль сроков действия»). Не обязательно blocking-валидация — достаточно мягкой подсказки в момент ввода, если похожая категория уже есть.

## Приоритет 3 — точечные наблюдения, не срочно

- **Онбординг-мастер: списки только на добавление** — уже задокументировано как осознанное решение и подсказка «Важно знать» в `docs/user-guide/scenarios.md`, но подсказки внутри самого мастера (не только в документации) не помешало бы для первого запуска без чтения гайда.
- **Печатная версия** проверена только для страницы продукта (единственное место с кнопкой печати) — работает чисто, навигация и кнопки действий корректно скрыты. Если печать понадобится на других детальных страницах, `print:hidden`-разметку придётся тиражировать по образцу уже существующей.
- **CSV-экспорт** выгружает то, что видно на экране (с учётом фильтров) — работает предсказуемо, но нигде явно не написано, что это именно «текущий экран», а не «весь раздел». Разница заметна только когда применён фильтр — стоит короткая подпись рядом с кнопкой при активном фильтре.

## Не проблема, но стоит зафиксировать (чтобы не поднимать как «забытое»)

- Пустые состояния всех списков/секций (например, «Пока нет исследований.») последовательны и понятны — без изменений.
- `WelcomeChecklist` на странице продукта корректно и мгновенно зачёркивает пункты по мере заполнения разделов — приятная деталь, работает как задумано.
- Дублирование записи, закрепление, «недавно просмотренное», лента активности — все точечные удобства из `archive/growth-plan.md` §1.4 подтверждены рабочими при ретесте, отдельно не перечисляются здесь.
